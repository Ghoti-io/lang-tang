# Divergence ledger

Every way lang-tang is allowed to differ from frozen ctang is a row below.
Nothing else is. ctang is the oracle (spine AD-16): the corpus is parsed by
both, and from the story that adds execution on, run by both, and a difference
that no row names fails the differential. ctang retires when the ledger is
**closed**, meaning no row is `open` (AD-3).

| Column | Meaning |
| --- | --- |
| `id` | `D-001`, `D-002`, ... Never reused. |
| `category` | `ctang-defect` (ctang is wrong and lang-tang is right), `limit` (a bound ctang has no equivalent of), `error-reporting` (how an error reaches the host), `rng` (the random generator). |
| `status` | `open` (nobody has decided yet), `recorded` (a deliberate departure, accepted), `fixed` (the difference is gone). Only a `recorded` row that names corpus files accepts a divergence on them, and it is **stale**, and fails the differential, once the named file stops diverging. |
| `ref` | The number of the language reference's section 13 item the row comes from, or `-`. |
| `corpus` | The corpus files (under `tests/corpus/`, comma separated) the row covers, or `-`. |
| `resolved-by` | The story that decides the row or records its end state. |
| `summary` | What differs and why. |

The table is validated by `tests/unit/test_ledger.cpp`: unique ids, valid
categories and statuses, every named corpus file exists, and a malformed row
fails (shown on a planted ledger). `tests/oracle/test_oracle.cpp` holds the
differential against it.

| id | category | status | ref | corpus | resolved-by | summary |
| --- | --- | --- | --- | --- | --- | --- |
| D-001 | ctang-defect | recorded | 9 | - | 10 | Section 13.9. Assigning through a string index is `Not supported` and the string is unchanged, but ctang discards the error unless it is the last value of the program: errors are values, and nothing tells the host about one that was swallowed. lang-tang leaves the string and the error as they are and lists the error (an expression statement whose value is an error that no variable holds is *discarded*, how `discarded`), which is D-006's mechanism; the language does not change. `tests/unit/test_errors.cpp` (`ADiscardedStringStoreIsListed`) holds it. |
| D-002 | ctang-defect | fixed | 13 | - | 9 | Section 13.13. `@` starts a date literal that the scanner recognises (now, today, relative, absolute, time zones) and the parser declares eleven tokens for but no grammar rule consumes. Both engines refuse every one of these files, at the same place, and the compiler has nothing to compile: the milestone adds no syntax, so lang-tang refuses `@` exactly as ctang does. Closed because there is no difference left to account for; a date type is a later language decision (section 14) and would open a new row. The `reject-date` corpus files are refused by both engines, which is what the oracle differential checks. |
| D-003 | rng | recorded | - | - | 10 | ctang shares one `random.global` across the whole process and seeds `random.default` from the clock. lang-tang gives each execution its own `random.global`, made on first access with a seed from the execution's seed sequence, and every read of `random.default` is a new generator seeded from the same sequence. The sequence is a `GLTANG_SeedSequence` the host makes once per group (a master seed, or operating-system entropy, and an atomic counter; draw k is splitmix64 of the master plus k golden gammas), handed to each execution; with none attached an execution makes a private one from entropy. Two executions given one master seed and one order of first use draw the same numbers. No generator is seeded from a clock. `seeded(n)` still matches `std::mt19937_64` word for word, and `random.global.set_seed(n)` still gives the error `Cannot change the seed of the global random number generator`. The corpus files `use-random-seeded.tang` print the same on both engines, since `seeded` does not read the sequence. |
| D-004 | limit | recorded | - | - | 9 | Budgets. ctang's only limit is call depth (`max_call_depth`, 512); a template can loop until the host kills it. lang-tang adds fuel, wall-clock, memory and guest-stack budgets, which ctang has no equivalent of, so a program that exhausts one has no ctang result to compare. No corpus file is named: the differential is parse-only and no budget acts at parse time (the one that does is D-016), and the execution corpus (`tests/corpus/script`, `tests/corpus/template`, run by both engines in the story's probes) has no file that exhausts a budget under ctang's own default. Call depth is the one budget both share, and `GLTANG_MAX_TREE_DEPTH` aside, lang-tang counts it the same way (the top level is a frame, so `max_call_depth + 1` guest frames). |
| D-005 | limit | recorded | - | - | 10 | The pause and unwind outcomes. A run that exhausts a budget pauses (`paused`: the host may raise the budget and resume) or unwinds (`GRCORE_ERR_LIMIT`); ctang has neither. A template call that exhausts its own budget scope is stopped at its boundary, with the limit error value as the call's value (policy `EMPTY`), the segments it finished (`SEGMENTS`), or a pause at the callee's file and line (`PAUSE`, a development setting). "lang-tang paused" and "ctang killed by the harness" are counted as agreement (AD-16). `tests/unit/test_template.cpp` holds each outcome. |
| D-006 | error-reporting | recorded | - | - | 10 | Errors reach the host. ctang loses an error that is not the last statement's value. lang-tang enters an error in the execution's error list when it is swallowed - printed (it renders as nothing), discarded by an expression statement that holds no variable, lost as the final value of a called template, or the stop of a template call by its budget scope - with the template it came from, the chain of template calls above it, and the file and line of the origin it carried from its creation; an error is entered at most once, a marker (`[INTEGER TOO LARGE]`) prints itself and is not swallowed, and the list is capped (default 1,024 entries, the rest counted). The host's switch logs every error at creation instead; its halt option ends the run at the first error with `GRCORE_ERR_GUEST`. Errors stay values inside the language, and no program can see the list. `tests/unit/test_errors.cpp` holds it. |
| D-007 | ctang-defect | fixed | - | - | 8 | Allocation failure in the grammar. About thirty ctang rules leaked their operands when a node's `create` refused, three (ranged `for`, `global`, `use IDENTIFIER;`) freed an adopted string twice, and flex called `exit(2)` when it could not allocate. lang-tang frees once, reserves the scanner's memory before the scan, and answers `OOM`. Observable only under allocation failure. |
| D-008 | ctang-defect | fixed | - | - | 8 | A string that fails UTF-8 validation was reported by ctang as out of memory. lang-tang reports the syntax error and names the cause. |
| D-009 | ctang-defect | recorded | - | - | 9 | The value of a loop or an untaken `if`. ctang leaks the last value it evaluated, which is the condition, so `while (false) {}` ends the program with `false` and `if (false) {}` likewise. lang-tang's loops and untaken `if`s have no value: the result is null. A taken `if` still has the value of its block. |
| D-010 | ctang-defect | recorded | - | - | 9 | A function that falls off its end. ctang returns the last statement's value, and for a function ending in an `if` or a loop the leaked condition (D-009), so the answer depends on how the body is written. lang-tang returns null. `return` is unchanged. |
| D-011 | ctang-defect | recorded | - | - | 9 | A trailing function declaration. A program whose last statement declares a function ends with `Function(n)` in ctang (and ctang's bytecode engine hangs on such a program, and crashes on `function f(f)`). In lang-tang a declaration does not change the result, so the program's result is the last expression statement before it, and a duplicate parameter name is a compile error. |
| D-012 | ctang-defect | recorded | - | - | 10 | `use` of a path nothing provides. With libraries, `use nothing;` binds null on both engines, but for a dotted path through a name nothing provides ctang binds the error `Not implemented` (an earlier ctang segfaulted on `use a.b.c as d;`), while lang-tang binds null in every case: the first name is looked up in the execution's libraries, then the program's, then the built-ins, and a name none of them has binds null and the program goes on. The rest of a path that does resolve is read with the attribute rule, so `use math.tau as t` is `Not implemented` on both. The corpus files `use.tang` and `use-as.tang` are parse-only differentials; `use-unknown-library.tang` prints the same on both engines. |
| D-013 | ctang-defect | recorded | - | - | 9 | `as string` on a container. ctang flattens every element to TRUSTED text, so a string that was HTML is no longer marked HTML once it has been through a container. lang-tang keeps each element's encoding, as it keeps them through concatenation. |
| D-014 | ctang-defect | recorded | - | - | 9 | Array `+` and `*` alias their elements in ctang: `a = [[1]]; b = a + a; b[0][0] = 9;` changes `a` too. lang-tang deep-copies the elements, as storing into a container already does. |
| D-015 | ctang-defect | recorded | - | - | 9 | The order a map prints and iterates in. ctang uses its hash table's order, which depends on the keys and the table's size. lang-tang keeps insertion order. A test that compares a printed map with more than one key sees it. |
| D-016 | limit | recorded | - | - | 9 | The tree-depth budget. The parser refuses a tree deeper than `GLTANG_MAX_TREE_DEPTH` (10,000) with `GLTANG_ERR_LIMIT` and no tree, so destroy, walk, count, print and the compiler are bounded on every tree that exists. ctang accepts deeper chains (a `1+1+...` of 20,000 terms parses) and overflows the C stack at some larger depth. No corpus file is deep enough to show it; `tests/unit/test_compile.cpp` and `tests/cli-test.sh` hold the cases: a tree 10,000 deep parses, compiles and runs, and one 10,001 deep is refused. |
| D-017 | limit | recorded | - | - | 9 | Two more bounds on recursion in the engine and the printer. A container nested deeper than `GLTANG_MAX_VALUE_DEPTH` (2,048) makes copy, equality and print give the error `Recursion Limit Exceeded` instead of recursing on the C stack; and the syntax-tree printer caps its indent at 256 levels so printing a tall tree is linear (it was quadratic). ctang has neither bound. |
| D-018 | error-reporting | recorded | - | - | 9 | Where an error came from. An error value in lang-tang records the file, line and function it was created at, which the host reads with `gltang_execution_result_error`; ctang's errors carry a message and nothing else. A message and a kind are the same in both. |
| D-019 | ctang-defect | recorded | - | - | 9 | `tang -e SOURCE`. ctang's `-e` runs the source as a template, so `-e 'print(1+2);'` prints the source's own text. lang-tang's `-e` is a script, as `-s` is, and `-t` makes it a template. Only the command differs; the library's two parse modes do not. |
| D-020 | limit | recorded | - | - | 10 | A template call. ctang has no template call: the language reference describes `use` and a function value, and a host that wanted a nested template ran another context. lang-tang's `use sidebar;` binds a template the host registered, and `sidebar()` runs it as a guest-to-guest call on the caller's stack under a budget scope of its own, taking no arguments (any is `Argument Count Mismatch`), with its own variables and its own output, whose value is the output as a string with every segment's encoding kept. No syntax is added: it is an ordinary call of a value. There is no ctang result to compare, so no corpus file is named; `tests/unit/test_template.cpp` holds the behaviour. |
| D-021 | ctang-defect | recorded | - | - | 10 | How a native function value prints inside a container. ctang prints `FunctionNative<0x55c4236505a0>(Callback<0x55c42362b3f0>, BoundObject<(nil)>)`, which holds two pointers and so differs from run to run. lang-tang prints `Function(native)` for a host's or the engine's native function and `Function(0)` for a template. A native function prints as nothing under `print` on both. |
| D-022 | error-reporting | recorded | - | - | 10 | Two error kinds ctang does not have, appended to the enum: `Limit Exceeded` (the value of a template call that its scope stopped) and `Host function failed` (a native function that returned false, or answered with text that is not UTF-8). The third appended kind, `Cannot change the seed of the global random number generator`, is ctang's own error and spelled as ctang spells it. A native function may answer with any kind of error the enum has. |
